DramaPilot · 短剧出海投放决策 Agent

2026.06 – 至今 · 短剧出海 · Agent

给一部国内短剧，Agent 盘点它的钩子，判断投哪个市场、主打哪个钩子、素材尺度开到几档，采纳后一键生成本地化素材并派发渲染。

Demo ↗GitHub ↗

核心逻辑

ingest读懂短剧
→
agent逐市场决策
→
produce生成本地化素材
→
dispatch派发 KrillinAI 渲染

关键做法与取舍

切决策，不卷生成

渲染交给开源 KrillinAI，自己只做决策层。

  • 4 段全链路打通。
  • 4 × 5 级：爽 / 恨 / 欲 / 贪四类情绪钩子，按 1–5 级打强度。
  • 每个市场出 2 版素材：激进冲量版和保守保户版。
  • 钩子强度 × 平台合规双维评估：合规风险超过 3 级的钩子在该市场禁用，换钩子再投，不直接否掉市场。
  • 从业者访谈后改方向：投手要的是把尺度推到平台红线，v2 把「敏感点提示」改成分市场的钩子资产；AI-as-Judge 自检乐观偏差和红线越界，并估算 ROAS 与成本。

公积金政策问答

2026.10 · RAG

同一个知识库、两种用法：市民模式过滤失效条款，坐席模式把它找出来标红。

市民模式 Demo ↗坐席模式 Demo ↗

核心逻辑

市民模式

基于 Dify 搭建的北京住房公积金政策问答，市民直接提问，只用生效条款作答、注明出处，缺信息先追问，答不了转人工。

问题分类政策咨询 / 分中心缴存 / 个人查询 / 超出范围 / 违规套取
→
按元数据检索只取生效、且非国管体系的条款
→
代码计算额度先提取参数
→
大模型按依据作答标注来源

坐席模式

给 12329 热线坐席用的辅助助手，输入市民诉求，输出参考答案、原文出处、推荐话术，并提醒哪些说法已失效。

坐席录入诉求
→
检索不过滤失效条款，故意找出旧规定
→
代码计算额度
→
按固定五段输出诉求 / 参考答案 / 推荐话术 / 需追问 / 已失效条款提醒

亮点数据

73% → 100%

计算题正确率（5 道计算题 × 每题 3 次），把装修提取、贷款额度、租房提取的公式计算从大模型交给代码

9/9

陷阱题实测全部通过（含过期条款、计算、体系分流、拒答、追问、坐席题）

约 12 秒

平均响应时间，推理强度调低后，原来约 30 秒

8 个官方来源整理成 46 条政策，其中 3 条已失效并标注替代关系。

关键做法与取舍

同一个知识库、两种用法

市民模式把失效条款过滤掉，坐席模式把它找出来标红。

市民模式

  • 每条政策带元数据：发布日期、生效 / 失效、适用体系（北京市 / 国管 / 全国）、来源类型（官方原文 / 媒体转述）。
  • 实测发现：不开过滤时，已失效的「无发票每月 1500 元」条款在检索结果中排第 2；开启过滤后不再出现。
  • 查个人数据、超出范围、违规套取三类问题走固定话术，不经过大模型。

坐席模式

  • 市民可能拿着旧说法来问（例如「以前每季度到账 4500 元」），坐席需要知道旧规定是什么、被哪条替代。
  • 回答给坐席看，不直接给市民，中间有人把关。

踩过的坑

  • 元数据手工填错（来源编号、日期）→ 结论：生产环境应由系统按字段自动生成标签。
  • 免费向量额度用完导致检索全空 → 换向量模型后维度不匹配 → 重建知识库。
  • 提速后模型先写结论再算，出现「先写 30 万再改口 25 万」→ 做对照实验，计算交给代码。
  • 免费的 Flash 模型拥堵，实测比旗舰模型还慢 → 选模型看实测而不是看名字。

个人作品演示，非官方服务，政策以北京住房公积金管理中心公布为准。

知己知彼 · AI 产品增长与营销打法传播图

2026.10 – 至今 · AI 产品增长 · 传播分析

选一次 AI 产品的推广，把它在社交平台上的传播还原成人物关系和传播链，再和产品内的增长、商业化动作对照着看。首批一个国内、一个海外：阶跃 STEPX Neo（B 站）对比 Manus Cue（X + Reddit）。

Demo ↗

核心逻辑

采集事件在 B 站、X、Reddit 上的内容与账号
→
智能判断大模型逐条判内容类型、情绪、对应的产品动作；规则推断传播关系
→
并入本体人和账号只有一张大图，跨事件复用
→
按事件切片关系图、时间泳道、传播链、对比

当前是 MVP：事件由人工选定，自动发现候选热门事件放在下一步。

亮点数据

358 条

传播内容入图，涉及 268 人、356 条关系

14 个

产品内增长与商业化动作（首发、邀请码、预售、定价等），和传播排在同一条时间线上

3 个平台

B 站、X、Reddit，同一个产品在不同平台的声量和口碑分开看

初步发现

  • 话题热度不等于产品声量：B 站话题活动「STEPX狂想计划」下，约三分之一投稿只挂了话题，内容和手机无关。看活动效果要用有效声量。
  • 同一个 Cue，X 上负面约 10%，Reddit 上约 41%。X 上是新用户在求码、晒功能；Reddit 上是老用户在抱怨原来的 Agent 入口换成了 Cue，而 Cue 还要邀请码。拉新在 X 做声量，代价落在存量用户身上。
  • Cue 的电话号码网页端 $9.99、iOS 端 $0.99，这个价差被博主做成「捡漏教程」互相搬运，成了首周中文区传播最广的内容之一：商业化漏洞反而成了增长素材。

以上为系统初判，抽检确认中。

关键做法与取舍

一张大图，按事件切片

人和账号只建一份本体，每个事件只取相关的部分来画；在多个事件里出现的人会被标出来。

  • 传播之外，把产品内的动作（邀请码、预售、定价）按时间和传播阶段排在一起，看哪一步带来了哪一波声量。
  • 直接证据和推断分开画：回复、引用、@ 画实线，按时间和内容推断的关系画虚线。
  • 机器判断先标「初判」：工作台里有抽检队列，人工修正写回本体，重跑管道时自动应用。

PM 面试前调研 Skill

2026.06 · Claude Skill · 开源

把「面试前调研一家公司」流程化的 Claude Skill：说一句「我下周面试 XX」，先问清 5 个参数，再按 6 个维度分组搜索，最后交付一份 8 个模块的面试准备包（默认 Word）。

GitHub ↗

核心逻辑

问清 5 个参数公司、岗位、岗位类型、个人背景、交付形式与深度
→
6 个维度搜索公司基础、近期动作、核心人物、指标与商业模式、竞品、PM 个人账号
→
按 8 个模块组织顺序固定
→
生成 Word脚手架脚本，改一个常量切换中英
→
给下一步建议2–3 个可执行动作

8 个模块：岗位定位与 JD 解读、公司画像、近 6 个月产品改动、PM 公开发言与账号挖掘路径、核心指标与瓶颈、竞品快评、入职 30 天计划、高概率问题与反问（5 + 5）。每个模块配中英模板和实战示例。

关键做法与取舍

拒答比瞎答好

查不到的指标写「公开信息不可得」，推演出的结论标「推断」，和已核实的事实分开。

  • 信号优于数据：每个事实后面跟一句「这意味着什么」，不堆资料。
  • 按公司所在市场选信息源：国内公司查脉脉、知乎、即刻、小红书、公众号；海外公司查 LinkedIn、X、Substack、Reddit、Hacker News。
  • 竞品快评按岗位类型换视角，30 天计划按候选人背景换写法；只用最近 12 个月的资料。
  • 对话用什么语言，交付就用什么语言；交付时说明这是公开信息合成，私域信息靠内推和一手访谈补全。
