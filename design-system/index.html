DramaPilot · 短剧出海投放决策 Agent

2026.06 – 至今 · 短剧出海 · Agent

给一部国内短剧，Agent 盘点它的钩子，判断投哪个市场、主打哪个钩子、素材尺度开到几档，采纳后一键生成本地化素材并派发渲染。

→
agent逐市场决策
→
produce生成本地化素材
→

关键做法与取舍

切决策，不卷生成

渲染交给开源 KrillinAI，自己只做决策层。

  • 4 段全链路打通。
  • 4 × 5 级：爽 / 恨 / 欲 / 贪四类情绪钩子，按 1–5 级打强度。
  • 每个市场出 2 版素材：激进冲量版和保守保户版。
  • 钩子强度 × 平台合规双维评估：合规风险超过 3 级的钩子在该市场禁用，换钩子再投，不直接否掉市场。
  • 从业者访谈后改方向：投手要的是把尺度推到平台红线，v2 把「敏感点提示」改成分市场的钩子资产；AI-as-Judge 自检乐观偏差和红线越界，并估算 ROAS 与成本。

公积金政策问答

2026.10 · RAG

同一个知识库、两种用法：市民模式过滤失效条款，坐席模式把它找出来标红。

市民模式 Demo ↗坐席模式 Demo ↗

核心逻辑

市民模式

基于 Dify 搭建的北京住房公积金政策问答，市民直接提问，只用生效条款作答、注明出处，缺信息先追问，答不了转人工。

问题分类政策咨询 / 分中心缴存 / 个人查询 / 超出范围 / 违规套取
→
按元数据检索只取生效、且非国管体系的条款
→
代码计算额度先提取参数
→
大模型按依据作答标注来源

坐席模式

给 12329 热线坐席用的辅助助手，输入市民诉求，输出参考答案、原文出处、推荐话术，并提醒哪些说法已失效。

坐席录入诉求
→
检索不过滤失效条款，故意找出旧规定
→
代码计算额度
→
按固定五段输出诉求 / 参考答案 / 推荐话术 / 需追问 / 已失效条款提醒

亮点数据

73% → 100%

计算题正确率（5 道计算题 × 每题 3 次），把装修提取、贷款额度、租房提取的公式计算从大模型交给代码

9/9

陷阱题实测全部通过（含过期条款、计算、体系分流、拒答、追问、坐席题）

约 12 秒

平均响应时间，推理强度调低后，原来约 30 秒

8 个官方来源整理成 46 条政策，其中 3 条已失效并标注替代关系。

关键做法与取舍

同一个知识库、两种用法

市民模式把失效条款过滤掉，坐席模式把它找出来标红。

市民模式

  • 每条政策带元数据：发布日期、生效 / 失效、适用体系（北京市 / 国管 / 全国）、来源类型（官方原文 / 媒体转述）。
  • 实测发现：不开过滤时，已失效的「无发票每月 1500 元」条款在检索结果中排第 2；开启过滤后不再出现。
  • 查个人数据、超出范围、违规套取三类问题走固定话术，不经过大模型。

坐席模式

  • 市民可能拿着旧说法来问（例如「以前每季度到账 4500 元」），坐席需要知道旧规定是什么、被哪条替代。
  • 回答给坐席看，不直接给市民，中间有人把关。

踩过的坑

  • 元数据手工填错（来源编号、日期）→ 结论：生产环境应由系统按字段自动生成标签。
  • 免费向量额度用完导致检索全空 → 换向量模型后维度不匹配 → 重建知识库。
  • 提速后模型先写结论再算，出现「先写 30 万再改口 25 万」→ 做对照实验，计算交给代码。
  • 免费的 Flash 模型拥堵，实测比旗舰模型还慢 → 选模型看实测而不是看名字。

个人作品演示，非官方服务，政策以北京住房公积金管理中心公布为准。

外壳与项目色

外壳始终保持中性，项目色只进入图标和缩略图。点击色值即可复制。

纸白／Paper

页面主背景、留白区域

暖黑／Ink

标题、正文、核心信息

消防车红／Red

交互状态、每页一处关键判断

暖灰白／Surface

分类头、成果底板、流程步骤

品牌红的边界
用于主按钮、链接，以及每页最多一处关键判断。单页约占 3%–5%，不用作错误色或普通标签色。

可读性
暖黑／纸白 18.15∶1；红色／纸白 5.35∶1。红色可用于短文字和按钮，长段正文仍用暖黑。

项目色的两个位置。每个项目单独设置 --pc，仅用于图标底色和缩略图。标题、标签、按钮和卡片底色始终使用外壳变量。

红橙撞色处理。红色或橙色系项目设置 data-accent-family="warm"，项目图标线条改为暖黑。上方「MiroFish 消歧 Agent」演示了这条规则。

签名元素 A。每页页眉统一使用 4 px 高、比例为 3∶1∶4 的暖黑—红—暖灰分段横线。它是固定的品牌签名，不随项目色变化；不再叠加超大号项目序号。

面试展示规范

同一套配色可以用于网页、PDF 和演示文稿，但字号需要按观看场景调整。

  • 一页一个结论。标题优先表达判断，正文补充依据；每页最多一处红色重点。
  • 屏幕阅读与投屏分开排版。1920 × 1080 演示画布建议：标题 64–80 px、正文 28–32 px、图注 22–24 px、四周安全边距 96 px。
  • 字数多就拆页。不要通过压缩字距、缩小字号或铺满卡片来塞入更多内容。
  • 数据与状态各有角色。图表比较使用暖黑与灰阶，目标序列通过标签与线型区分；报错使用暖黑、叹号和文字说明，品牌红只服务交互与一处关键判断。
  • 中文保持完整字形。不用手写、圆体、倾斜艺术字，也不强行把汉字拉长、压扁或加粗描边。
  • 交付前检查字体。网页只使用本地系统字体；PDF 应嵌入允许嵌入的字体。正式面试前在实际设备上检查中文、数字和换行。
